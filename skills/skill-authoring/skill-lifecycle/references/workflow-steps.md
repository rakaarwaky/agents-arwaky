# Workflow Steps

The full per-step checklist for a `skill-lifecycle` run. The Global Rules in SKILL.md apply to every step.

- [ ] **Step 1: Confirm audit root** — default `/home/raka/agents-arwaky/skills`, a specific category, or the user's path. Reject a path that resolves to a file; stop if the directory holds no `SKILL.md` subfolders.
- [ ] **Step 2: Inventory** — list every skill folder, read each `SKILL.md` frontmatter and body.
- [ ] **Step 3: Group** — cluster skills by semantic scope using `description` and trigger terms; verify clusters against body content (two descriptions that rhyme can be different jobs).
- [ ] **Step 4: Classify** — each cluster is duplicate (identical scope), variant (same domain, distinct scenarios), or separate jobs.
- [ ] **Step 5: Dry Run & Approval** — generate the planned report (see report format). Present it and ask: *"Here is the planned prune. Shall I proceed with the git snapshot and execute these changes?"* Wait for confirmation. With `--auto` or `--evolution`, skip this gate and proceed straight to Step 6.
- [ ] **Step 6: Snapshot** — `git add -A && git commit -m "snapshot: before skill-lifecycle"` (or `git stash` if the tree is dirty for other reasons). If the tree holds unrelated in-progress changes, record the current `HEAD` SHA as the rollback target and stage only the skill-tree paths you touch — never `git add -A` into the same commit as unrelated work. Use explicit paths (`git add skills/<category>/ skills/CATALOG.md`) and verify the staged set with `git status --short` — a path typo or a sibling subagent committing concurrent work in the same checkout silently pulls unrelated deletions into the commit; unstage anything that is not part of the prune.
- [ ] **Step 7: Execute** — merge per the Phase 2 table in SKILL.md. When merging, delete the redundant folders (keep one canonical folder name, preferring the existing skill whose `name:` in frontmatter matches the surviving scope).
- [ ] **Step 8: Update** — update the category `DESCRIPTION.md` if a folder was removed or renamed; if a category is left completely empty, delete the category folder and its `DESCRIPTION.md`. Reconcile `skills/CATALOG.md`: drop the row for every dropped skill, add/update the row for the surviving skill's new description, adjust the category's skill-count column. The catalog is a generated artifact (`aa skills catalog [--check]`), so after the manual edit run that command to confirm it is consistent before committing.
- [ ] **Step 9: Verify** — every remaining `SKILL.md` parses as valid frontmatter, all `references/` links resolve (including cross-links within the `references/` set, not just from `SKILL.md` to `references/`), no two skills share a `name:`, and `aa skills validate` reports no issues. Confirm `skills/CATALOG.md` still matches the on-disk state (or run `aa skills catalog` to regenerate). If verification fails, trigger the Rollback Protocol.
- [ ] **Step 10: Report** — output the final executed `skill-lifecycle report`.
