# LLM Writing — Step 3: System and Process Patterns

Structures for text that describes a system, workflow, or dependency chain.

**Goal:** every system description ships machine-readable structure — diagram, dependency map, state machine, data flow, or invariants — with real identifiers, not prose.

## Element Table

| Element | Format | Required content | Pick when |
|---------|--------|------------------|-----------|
| Diagram | Mermaid in a `mermaid` code block | Node labels = real identifiers (module, path, service, step) | 3+ components; spatial relationships matter |
| Dependency map | Table: Component, Depends on, Depended on by | Both directions | Impact analysis needed; add `Generated by <command>, <date>` |
| State machine | Table: From, Event, Guard (boolean), To, Action | Every transition has an exact boolean guard | Discrete states with transitions |
| Data flow | Ordered table: Step, Source, Transform, Sink | Name the file or function at each step | Sequential processing |
| Invariants | Table: ID, Invariant, Enforced by | Name the enforcing test, check, or type | Constraints that must always hold |

Dependency maps that can be produced by one command are not duplicated — give the command instead. Every generated artifact carries a `Generated by <command>, <date>` line so staleness is detectable.

## Completion

- Every system, workflow, or dependency chain in the text has one of the elements above.
- All node labels and table cells are real identifiers from the source, not generic placeholders.
- No state machine transition without a boolean guard; no invariant without its enforcer.
